# Domain docs

This is a single-context project. Keep the domain glossary at the repository root in `GLOSSARY.md` and architectural decision records in `docs/adr/`.

Before exploring a domain area, read the glossary and any ADRs that touch that area. If either does not exist yet, proceed without creating one until terminology or a decision needs to be recorded.

Use glossary terms consistently in issue titles, specs, and code. Surface conflicts with existing ADRs instead of silently overriding them.
